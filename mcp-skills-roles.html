Primitiva 1 de 3

MCP — Model Context Protocol

O protocolo aberto criado pela Anthropic em 2024 que padroniza como agentes de IA se conectam a ferramentas externas. Pensa no MCP como o USB-C dos agentes: antes cada integração era customizada; agora existe protocolo comum.

🔌

MCP — A camada de integração

// standard protocol for agent-to-tool communication
Um servidor MCP expõe capacidades (ler arquivo, consultar API, executar comando) que qualquer cliente MCP (Claude Desktop, Claude Code, agentes customizados) consome de forma padronizada. O agente ganha braços — deixa de operar apenas com o que sabe e passa a operar com o que consegue observar em tempo real.
Casos de uso em SRE
▸Consultar Prometheus/Grafana para métricas em tempo real
▸Listar pods, logs e eventos no Kubernetes
▸Buscar logs no Splunk com queries específicas
▸Revisar PRs e criar issues no GitHub/GitLab
▸Verificar alertas ativos no PagerDuty/Opsgenie
▸Consultar status de deploy no Harness/ArgoCD
▸Abrir chamados no Jira/ServiceNow automaticamente
▸Consultar Datadog para APM e traces
Exemplo de configuração MCP
~/.claude/config.json JSON
// Configuração de servidores MCP para SRE bancário { "mcpServers": { "prometheus": { "command": "mcp-server-prometheus", "env": { "PROM_URL": "https://prom.itau.corp" } }, "kubernetes": { "command": "mcp-server-k8s", "env": { "KUBECONFIG": "/etc/k8s/prod-readonly.yaml" } }, "splunk": { "command": "mcp-server-splunk", "env": { "SPLUNK_TOKEN": "${SPLUNK_READONLY_TOKEN}" } }, "harness": { "command": "mcp-server-harness", "env": { "HARNESS_API_KEY": "${HARNESS_READONLY_KEY}" } } } }
"Sem MCP, o agente é um consultor externo que só sabe o que você contou. Com MCP, ele é um SRE júnior que consegue abrir o Grafana, o Splunk e o kubectl ao mesmo tempo — e correlacionar tudo em segundos."
Primitiva 2 de 3

Skills — conhecimento executável

Pacotes de instruções, código e templates que ensinam o agente a executar tarefas específicas seguindo o padrão do time. Uma Skill vira conhecimento operacional reutilizável — o playbook do time codificado em algo que o agente sabe consultar e aplicar.

🎓

Skills — Playbooks do time codificados

// SKILL.md + scripts + templates + examples
Uma Skill agrupa um SKILL.md (instruções em linguagem natural sobre quando e como usar), scripts auxiliares (Python, bash), templates e exemplos. O agente lê a Skill certa na hora certa e passa a executar a tarefa exatamente do jeito que o time faz — nomenclatura, formato de output, ferramentas usadas.
Skills típicos em uma operação SRE
▸incident-triage: coleta logs, correlaciona métricas, gera timeline
▸iac-review: valida Terraform/Helm por padrões do banco
▸postmortem-writer: gera documento no template do time
▸pre-deploy-check: valida DORA + coverage + security
▸rca-5-whys: root cause analysis estruturada
▸k8s-troubleshoot: diagnóstico de pod/deployment/service
▸slo-report: gera relatório mensal de SLO
▸runbook-executor: executa runbook aprovado com aprovação
Estrutura de uma Skill de exemplo
skills/itau-incident-triage/SKILL.md MARKDOWN
--- name: itau-incident-triage description: Triagem inicial de incidente P1/P2 seguindo padrão Itaú trigger: alerta PagerDuty severity=high OR palavra "incidente" no chat --- # Skill: Itaú Incident Triage ## Quando usar Sempre que chegar alerta P1/P2 do PagerDuty ou pedido explícito de triagem de incidente em produção. ## Passos obrigatórios 1. Consultar Splunk com query padrão do serviço afetado 2. Consultar Datadog: latência p99, error rate, throughput 3. Consultar Harness: último deploy nas últimas 4h 4. Consultar Kubernetes: pods do serviço + eventos recentes 5. Correlacionar timestamps: alerta ↔ deploy ↔ anomalia ## Output esperado - Timeline de eventos em formato Markdown - Hipótese principal de root cause - Ações recomendadas (nunca executar sem aprovação) - Chamado no ServiceNow com template ITAU-INC-P1 ## Ferramentas MCP necessárias splunk · datadog · harness · kubernetes · servicenow ## Restrições - NUNCA executar rollback sem aprovação humana - NUNCA acessar dados PII/financeiros nos logs - SEMPRE registrar todas as consultas no audit log
"Skills transformam conhecimento tribal em conhecimento operacional. O runbook que só o Zé sabia agora vira algo que qualquer agente executa exatamente do jeito certo, na 3h da manhã, sem depender do Zé estar acordado."
Primitiva 3 de 3

Roles — governança e permissão

Configuração de permissões e responsabilidades do agente. Define o que ele pode fazer, em qual ambiente, com qual nível de autonomia. Em ambiente regulado (banco, BACEN, LGPD), Roles são o que viabiliza usar agente com segurança — não é opcional.

🛡️

Roles — Guardrails de autonomia

// least-privilege access control for AI agents
Uma Role define o escopo de ação do agente: quais Skills pode invocar, quais servidores MCP pode consultar, em qual ambiente pode operar e quando precisa de aprovação humana. É o mesmo princípio de least-privilege que aplicamos a service accounts — só que agora para agentes de IA.
Matriz de Roles em SRE bancário
Role Ambiente Ações permitidas Aprovação
observer prod Ler logs, métricas, status ✓ Não
analyst prod Ler + gerar relatórios, RCAs ✓ Não
operator homolog Ler + executar runbooks ✓ Não
deployer homolog Deploy + rollback ✓ Não
prod-operator prod Ler + executar runbooks aprovados ⚠ Sim, por ação
prod-deployer prod Deploy + rollback em prod ⚠ Mandatória
Configuração de Role em código
roles/prod-analyst.yaml YAML
apiVersion: agent.itau.corp/v1 kind: AgentRole metadata: name: prod-analyst spec: environment: production mcpServers: - prometheus # read-only - datadog # read-only - splunk # read-only - harness-readonly # read-only - kubernetes-ro # read-only, no exec allowedSkills: - itau-incident-triage - rca-5-whys - postmortem-writer - slo-report forbiddenActions: - deploy - rollback - delete - access-pii requiresApproval: false # read-only, sem risco auditLog: mandatory # toda ação registrada
"Role é o cinto de segurança. Sem ele, o agente vira um estagiário com acesso root em produção — perigoso demais para ambiente regulado. Com ele, o agente vira um profissional com escopo claro e supervisão adequada."

Como os três se orquestram

Na prática, MCP, Skills e Roles trabalham juntos como camadas complementares. Um alerta P1 dispara uma cadeia orquestrada que envolve os três.

Sem os três primitivos vs. com os três primitivos

Agente genérico (sem MCP/Skills/Roles)
❌Só sabe o que foi contado no chat
❌Sem acesso a métricas ou logs reais
❌Sem padrão de execução — respostas divergem por conversa
❌Sem controle de permissão — risco em ambiente regulado
❌Alucina dados de sistema por falta de fonte real
❌Não deixa audit trail rastreável
Agente operacional (MCP + Skills + Roles)
✅Consulta Splunk, Datadog, K8s, Harness em tempo real
✅Segue padrão do time em toda execução
✅Escopo controlado por Role — least-privilege
✅Zero alucinação — sempre com dado de fonte real
✅Audit log completo de toda ação
✅Aprovação humana onde regulação exige
Sinergia

Integração com a esteira Harness

MCP + Skills + Roles não substituem o Harness — trabalham em cima dele. O agente vira uma camada de inteligência que consulta, analisa e sugere ações que a plataforma executa.

🔗 Como o agente se integra ao pipeline Harness
Uma pipeline típica no Harness passa a ser observada, analisada e complementada por agentes com Skills específicos para cada estágio.
1
Pre-commit — Code review de IaC
Role iac-reviewer · Skill terraform-review · MCP github analisa PR de infra antes do merge, valida padrões do banco e comenta no PR automaticamente.
2
Build — Análise de teste
Role ci-analyst · Skill test-failure-diagnosis · MCP harness ao quebrar um teste, o agente lê o log, correlaciona com commits recentes e sugere o fix.
3
Deploy — Verificação assistida
Role deploy-analyst · Skill canary-verification · MCP prometheus + datadog complementa o CV nativo do Harness com análise contextual profunda.
4
Post-deploy — Health check inteligente
Role prod-analyst · Skill post-deploy-check · MCP splunk + k8s + datadog monitora as primeiras 2h pós-deploy e alerta sobre padrões anômalos que o CV não pega.
5
Incidente — Triagem automática
Role prod-analyst · Skill itau-incident-triage · MCP splunk + datadog + harness + k8s quando o CV do Harness detecta anomalia e faz rollback, o agente já entrega o RCA pronto para o SRE.
6
Postmortem — Documentação automática
Role analyst · Skill postmortem-writer · MCP harness + jira após incidente resolvido, o agente compila timeline, ações tomadas e recomendações no template do time.
"A esteira Harness cuida da execução com governança. O agente com MCP + Skills + Roles cuida da inteligência contextual. Juntos, formam um sistema onde a máquina executa o que é seguro e o humano decide o que é sensível — com contexto pronto na mão."
